# FunASR 能力研究报告

## 当前使用情况

| 组件 | 模型 | 作用 |
|------|------|------|
| ASR（语音识别） | Paraformer-zh (220M) | 中文语音 → 文本 |
| VAD（语音检测） | FSMN-VAD | 切分语音/静音段 |
| SPK（说话人分离） | CAM++ (7.2M) | 区分老师和家长 |
| PUNC（标点恢复） | CT-PUNC | 自动加标点 |

我们只用到了 FunASR 生态的一小部分。以下是尚未使用但**可能对销售通话分析有价值**的能力。

---

## 一、情感识别（Emotion Detection）

### 可用模型

| 模型 | 参数量 | 能力 |
|------|:---:|------|
| **SenseVoiceSmall** | 234M | ASR + 情感 + 音频事件 + 语种，多合一 |
| **emotion2vec+base** | ~90M | 专用情感识别，7 类情感 |
| **emotion2vec+large** | 300M | 更高精度，4 万小时训练 |

### 支持的情感类别

```
HAPPY（开心）、SAD（伤心）、ANGRY（愤怒）、
DISGUSTED（厌恶）、SURPRISED（惊讶）、
NEUTRAL（中性）、UNKNOWN（未知）
```

### 对成交分析的价值

| 场景 | 情感信号 | 分析意义 |
|------|----------|----------|
| 家长说"太贵了" | **愤怒/厌恶** vs **中性** | 真抗拒 vs 随口说说，判断价格异议的严重程度 |
| 家长说"我再考虑考虑" | **犹豫（sad+neutral 混合）** | 可能是拖延型家长的信号 |
| 老师介绍课程时家长回应 | **开心/惊讶** | 兴趣信号，说明痛点被击中 |
| 通话结尾 | **满意/中性** vs **不耐烦** | 判断成交概率 |
| 整通电话情感曲线 | 从负面→正面 或 一直中性 | 评估老师的情绪引导能力 |

### 集成方式

SenseVoice 和 Paraformer 不能在同一 pipeline 中共用（SenseVoice 不支持 CAM++ 说话人分离所需的时间戳）。有两种方案：

**方案 A：双模型并行**
```
Audio ──→ Paraformer + CAM++（ASR + 说话人分离，当前方案）
     └─→ SenseVoice（情感 + 事件检测）

合并：将 SenseVoice 的情感标签按时间戳对齐到 Paraformer 的 segments
```

**方案 B：替换为 SenseVoice + 独立说话人分离**
```
Audio ──→ SenseVoice（ASR + 情感）
     └─→ CAM++ standalone（仅说话人分离）
     
然后按时间戳合并
```

> 方案 A 更稳妥，不破坏当前工作流，情感作为额外维度的 annotation 叠加到现有 segments 上。

## 二、音频事件检测（Audio Event Detection）

### 可检测的事件类型

SenseVoice 支持检测：
- **掌声 / 笑声**：对话氛围指标
- **咳嗽 / 叹气**：家长犹豫或不耐烦的信号
- **BGM / 铃声**：环境干扰，影响通话质量判断
- **静音/长时间停顿**：尴尬沉默，可能意味着沟通断层

### 对成交分析的价值

| 事件 | 含义 |
|------|------|
| 家长**叹气** | 犹豫、压力、不情愿 |
| 老师/家长**笑声** | 亲和力建立成功，关系升温 |
| **长时间沉默** | 老师推成交后家长不回应 → 可能抗拒 |
| **打断/重叠说话** | 老师急于推销 vs 家长急于表达顾虑 |

> 这些事件可以作为模块2/3 的**额外观察输入**，让 LLM 有更丰富的分析素材。

---

## 三、说话人声纹识别（Speaker Verification）

### CAM++ 的隐藏能力

CAM++ 本身是一个**说话人 embedding 模型**，除了说话人分离，还能：
- 提取每个说话人的 192/512 维声纹向量
- 跨录音匹配同一说话人

### 对成交分析的价值

| 场景 | 应用 |
|------|------|
| **多次通话关联** | 识别"这个家长之前打过电话"，关联历史分析 |
| **身份验证** | 确认打电话的是报名时的家长本人还是其他家庭成员 |
| **老师识别** | 如果多个老师使用系统，自动识别是哪位老师的通话 |

## 四、流式识别（Streaming ASR）

### 可用模型

- `paraformer-zh-streaming`：流式版 Paraformer
- `Fun-ASR-Nano`（800M，2025.12）：支持流式，首字延迟 160ms

### 对成交分析的价值

当前是**离线批处理**（打完电话后分析）。如果切换到流式：

- **实时辅助**：老师在通话中，系统实时转写 + 提示"家长是价格敏感型，建议不要直接报价"
- **实时预警**：检测到家长情感变负面时提醒老师调整策略

> 这是一个远期方向，需要架构调整（从批处理 Agent → 实时 Agent）。

---

## 五、重叠语音处理（Overlap Detection）

### EEND-OLA 模型

传统 CAM++ 管线对**两人同时说话**处理不好。FunASR 提供 EEND-OLA 模型：
- 端到端重叠语音分离
- 支持最多 8 人同时说话

### 对成交分析的价值

销售通话中重叠说话很常见：
- 老师急于解释 vs 家长急于提问 → **沟通冲突信号**
- 家长打断老师报价 → **价格焦虑信号**
- 老师打断家长说顾虑 → **推销过激信号**

---

## 六、多语种识别（Language ID）

SenseVoice 支持：中/粤/英/日/韩

如果销售通话中有中英混杂（国际学校家长、英语培训机构），SenseVoice 可以标注每段的语种。

---

## 七、逆文本正则化（ITN）

将"一千七百九十九" → "1799"、"百分之五十" → "50%"

对成交分析的价值：价格、分数、百分比等信息更加结构化，便于模块2/3 提取关键数字。

---

## 推荐优先级

| 优先级 | 能力 | 理由 | 工作量 |
|:---:|------|------|:---:|
| **P0** | 情感识别（方案A） | 直接增强模块2/3 的分析深度，家长情感是成交信号的关键维度 | 中 |
| **P1** | 音频事件（叹气/笑声/静音） | 轻量级附加，与情感检测一起部署 | 低 |
| **P2** | 声纹识别（跨通话关联） | 需要 CRM/数据库支持，更适合后续 Agent 化阶段 | 高 |
| **P3** | 重叠语音检测 | 需要换模型或加一路推理 | 中 |
| **P4** | 流式识别 | 架构需要从批处理改为实时，变化大 | 高 |

## 快速验证：情感检测

不需要改现有代码，用 SenseVoice 单独测试情感识别：

```python
from funasr import AutoModel

emotion_model = AutoModel(
    model="iic/SenseVoiceSmall",
    device="cpu",
)

# 对同一段录音跑情感检测
result = emotion_model.generate(
    input="data/input/2391069820黄科惠.mp3",
    use_itn=True,
)

# 输出包含情感标签的文本
# 格式: "<|HAPPY|>文本内容<|NEUTRAL|>文本内容..."
print(result[0]["text"])
```

可以先跑一下，看看输出长什么样，再决定是否集成。
